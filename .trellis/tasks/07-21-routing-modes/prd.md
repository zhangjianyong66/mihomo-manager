# 新增三模式路由与实时链路

## Goal

让用户能够通过 `mm` 明确选择全局代理、规则分流或全局直连，并能确认配置模式、实际运行模式、系统代理入口和每条活动连接的真实出站链路，消除“看到多个策略组却无法判断流量去向”的问题。

## Background

- 当前 TUI 和 CLI 没有专用的 mihomo 运行模式切换入口，只能编辑完整配置并手动热重载。
- 当前订阅更新会重建 `rules` 为 `MATCH,🌐 代理`，可能覆盖已应用的大陆直连分流。
- 当前 `cn` 预设使用完整 Geo 数据，并把 `MATCH,GLOBAL` 放在保留规则之前，可能形成不可达规则；写入后也不会自动热重载。
- 当前机器的系统代理仍指向 xray，而 mihomo 使用另一监听端口；模式状态必须区分“mihomo 已生效”和“桌面流量是否实际进入 mihomo”。

## Requirements

### R1 三种运行模式

- 提供全局代理 `global`、规则分流 `rule`、全局直连 `direct` 三种 mihomo 运行模式。
- `global` 模式下所有流量进入内置 `GLOBAL` 组，并使用该组当前节点。
- `direct` 模式使用 mihomo 原生 Direct 模式，所有流量绕过规则和代理节点。
- `rule` 模式按 R2 的顺序分流，未命中直连规则的流量进入 `🌐 代理`组。
- 保留 `GLOBAL`、`🌐 代理`、`🎯 直连`三个策略组的展示，并明确策略组与运行模式不是同一概念。

### R2 Rule 分流契约

- 本机地址和局域网 IPv4/IPv6 地址始终直连。
- 保留有效的用户自定义规则；自定义规则优先于白名单和默认 CN 分流。
- 白名单域名直连。
- 中国大陆域名通过 CN 域名规则集直连，中国大陆 IPv4/IPv6 通过 CN IP 规则集直连。
- 其他流量通过 `🌐 代理`组。
- 生成规则时移除旧的兜底 `MATCH`、重复的 manager 管理规则和不可达规则，最终只保留一个末尾兜底规则。
- Rule 模式同时管理 DNS 分流：大陆域名使用国内解析链路，境外域名使用经代理的加密 DNS，代理服务器域名使用独立直连解析以避免循环；本机和局域网解析保持直连。
- 兼容的用户 DNS 自定义项应保留，模式切换不得无差别覆盖整个 DNS 配置。

### R3 CN 专用规则集

- 使用 MetaCubeX 官方 `meta-rules-dat` 的 CN 域名和 CN IP `.mrs` 规则集，不下载本功能不需要的完整全球 Geo 数据。
- 安装器固定明确版本或提交及 SHA-256，支持显式覆盖下载基地址和引用，不自动切换第三方镜像。
- `make install` 与远程 bootstrap 共用 `scripts/install.sh` 的同一下载实现。
- 首次安装缺少规则集时，下载或校验失败必须使安装失败；已有有效缓存时，升级下载失败应告警并继续使用旧缓存。
- 下载写入临时文件，校验通过后原子替换；安装状态记录来源、版本、摘要和路径。
- mihomo 每 24 小时自动更新规则集；更新失败继续使用上一份有效缓存。

### R4 持久化与事务切换

- 模式切换必须持久化到配置，并在 core 运行时同步到实际运行态。
- 切换流程包含备份、生成、校验、原子写入、运行态更新和结果核验；任一步失败时恢复原配置和原运行模式。
- core 停止时允许保存并校验模式，不隐式启动 core；下次启动生效。
- 默认保留已有活动连接，并提示旧连接数量；用户可选择关闭所有 mihomo 活动连接，使新模式立即覆盖连接。
- 模式切换不得修改系统代理、停止 xray 或抢占其他进程端口。

### R5 订阅与升级兼容

- 全新安装默认使用 Rule 模式；升级保留现有配置模式，缺少 `mode` 时按 Rule 处理并在首次成功写入时显式保存。
- 订阅更新只能更新节点相关内容，必须保留模式、manager 规则、用户自定义规则、白名单、DNS 分流和规则集配置。
- 保留 `GLOBAL` 与 `🌐 代理`各自选中的节点；原节点消失时回退到首个可用节点并明确提示。
- 安装和升级不自动启动 mihomo core，也不自动修改系统代理。

### R6 TUI、CLI 与 daemon

- CLI 提供 `mm mode status`、`mm mode set global|rule|direct`，并支持 table/json 输出。
- `mm mode set` 支持关闭活动连接的显式选项。
- TUI 提供运行模式页面，展示配置模式、实际运行模式、模式说明和实际选中节点。
- TUI 与 CLI 必须调用同一 daemon 能力，不允许各自直接改写 YAML。
- 安装器安装、启用并启动 systemd user manager daemon，但不启用 linger、不使用 sudo、不启动 mihomo core；无 systemd 用户会话时只安装 unit 并提示 `mm daemon run`。
- 升级可重启 manager daemon，但不得擅自改变 mihomo core 运行状态。
- 全新安装且 `config.yaml` 由安装器创建时，安装流程自动创建恢复点并注册、激活 legacy profile，使 daemon 能力开箱可用。
- 升级发现已有用户配置时不得静默注册；TUI 与 CLI 必须提示用户显式执行 `mm migrate plan` 和 `mm migrate apply`。
- legacy 注册只建立快照和 manager 元数据，不改写源配置、不启动 core、不修改系统代理；无 systemd 用户会话时不强行创建临时后台 daemon。

### R7 真实链路与入口诊断

- CLI 提供活动连接查询和流式跟随能力，TUI 提供对应实时连接视图。
- 每条活动连接展示目标、命中规则、出站链路、最终节点和上下行流量；数据必须来自 mihomo 运行态，不得仅根据静态配置推测。
- 默认不持久化连接历史。
- 模式状态同时展示 mihomo 实际监听地址和系统代理入口；系统代理未指向 mihomo 时明确警告桌面流量不会使用当前模式。
- 只检测系统代理，不自动接管 GNOME、环境变量或其他代理进程。

## Acceptance Criteria

- [ ] AC1：三种模式均可通过 CLI 和 TUI 设置；运行中的 core 切换后配置模式与实际运行模式一致，停止的 core 显示“下次启动生效”。
- [ ] AC2：Global 模式的测试连接实际链路包含 `GLOBAL` 及其当前节点；Direct 模式的测试连接实际链路为 `DIRECT`。
- [ ] AC3：Rule 模式下本机/局域网、中国大陆域名和中国大陆 IPv4/IPv6 直连，非大陆流量进入 `🌐 代理`当前节点。
- [ ] AC4：用户自定义规则和白名单按约定优先级生效，最终规则列表只有一个末尾兜底且不存在兜底后的不可达规则。
- [ ] AC5：Rule 模式的 DNS 查询符合大陆直连、境外代理、代理服务器防循环的契约，模式切换失败时 DNS 与路由配置一并回滚。
- [ ] AC6：首次安装能下载并校验两份固定版本 `.mrs`；无缓存下载失败时安装失败，有缓存升级失败时保留旧文件；两种安装入口覆盖同一实现。
- [ ] AC7：规则集每 24 小时更新，失败不破坏有效缓存；安装状态包含可审计的规则集元数据。
- [ ] AC8：订阅更新前后模式、规则、白名单、DNS 和仍存在的节点选择保持不变；消失节点产生明确回退提示。
- [ ] AC9：切换事务在配置校验、文件写入、运行态更新或核验失败时恢复原配置和原运行模式。
- [ ] AC10：默认不关闭活动连接；显式关闭选项只终止 mihomo 活动连接。
- [ ] AC11：实时连接视图能够展示 mihomo 返回的命中规则与完整出站链路，CLI 跟随输出可被逐行消费且不落库存储。
- [ ] AC12：系统代理未进入 mihomo 时，状态页和 TUI 均显示入口不匹配警告，但不会修改系统代理或影响 xray。
- [ ] AC13：systemd 用户会话可用时安装后 manager daemon 已启用并运行、core 保持停止；不可用时 unit 已安装并给出可执行提示。
- [ ] AC14：安装脚本测试、Go 单元/集成测试、race、vet、Shell 语法检查和 Linux amd64/arm64 无 CGO 构建全部通过。

## Out of Scope

- 自动修改或恢复 GNOME 系统代理、shell 代理环境变量。
- 自动停止、重配置或迁移 xray。
- 持久化浏览历史或活动连接历史。
- macOS/Windows 安装和系统代理支持。
- 本任务之外的任意规则可视化编辑器；继续保留完整配置编辑入口。

## Planning Constraints

- 这是多 milestone 任务。父任务只承载总需求、跨 milestone 验收和执行顺序；实现必须按子任务独立规划、测试、提交和恢复。
- 默认只执行用户明确指定的 milestone，不在一次执行请求中自动连续完成全部 milestone。

# 恢复节点管理自动测速功能

## Goal

重新设计 TUI“节点管理”的测速交互：进入节点切换列表时立即显示已有测速结果，但不自动发起探测；用户通过快捷键明确触发单节点或批量测速。

## Background

- 当前 daemon、CLI 测速链路仍然存在：`mm node test` 通过 `/v1/nodes/test` 流式返回结果；2026-07-22 在真实 running core 上以 `--group '🌐 代理' --limit 3 --concurrency 3` 验证，3 个节点均成功返回延迟。
- 当前 TUI 在进入代理组以及成功切换节点后都会隐式发起批量测速；切换成功时还会先清空页面已有结果。最终产品意图是不执行这两类隐式探测。
- mihomo `/proxies` 为每个可测速节点返回运行时 `history`，元素包含测试时间与延迟；2026-07-22 已在真实 controller 上确认一个节点存在多条历史记录。
- 当前 app Group/Node DTO、daemon 查询接口与 TUI 都没有传递 mihomo history；TUI 的 `switchNodeDelay` 仅是当前页面内存，并在进出页面或切换节点时清空。
- 当前 `/v1/nodes/test` 只接收 profile、group、concurrency、limit，不能指定一个确切节点；实现单节点测速需要扩展跨层请求契约。
- mihomo history 可跨 TUI 会话复用，但属于 core 运行时状态，core 重启后不保证保留；跨 core 重启持久化需要由 manager 新增存储所有权和生命周期规则。
- 当前真实 `🌐 代理` 组超过 120 个候选，TUI 原有 `Limit: 120` 会使“全部测速”静默遗漏后续节点。
- README 仍描述“切换最快节点”，与本次确认的“测速只更新结果、切换必须由用户确认”不一致。

## Requirements

- R1：保留 daemon-backed 能力边界，TUI 不直接访问 mihomo controller。
- R2：节点测速必须继续使用有界低并发和可取消的流式调用；CLI 可保留显式数量上限，TUI 的整组批量测速不得静默截断。
- R3：延迟结果必须与所属代理组和节点对应，失败或超时应有可见状态，不能误报为成功延迟。
- R4：进入节点切换列表时不得自动触发测速，只读取并展示可用的历史测速结果。
- R5：节点切换列表必须提供快捷键，对当前选中节点发起单节点测速。
- R6：节点切换列表必须提供快捷键，对当前代理组中的可测速节点发起批量测速。
- R7：单节点与批量测速只更新结果，不得隐式切换当前节点；节点切换仍由用户按 Enter 明确执行。
- R8：测速过程中应显示明确的进行中状态；批量结果应逐项刷新，且用户离开页面或开始另一轮测速时取消旧任务。
- R9：历史测速结果直接读取 mihomo 运行时 history，不写入 SQLite；core 重启后没有 history 的节点显示“未测速”。
- R10：节点列表每个节点只展示最新一次有效历史延迟和相对时间，例如 `238ms · 9分钟前`；不在列表中展开完整历史序列。
- R11：节点切换列表使用 `t` 对光标所在节点进行单节点测速，使用 `a` 对当前代理组进行批量测速；快捷键及含义必须显示在页脚。
- R12：批量测速覆盖当前代理组中的全部可测速节点，不受 TUI 分页或旧 120 节点上限截断；保持有界低并发并报告完整进度。
- R13：测速进行中按 `Esc` 只取消当前测速并停留在节点列表，保留已完成结果；空闲时按 `Esc` 才返回代理组列表。
- R14：节点最新一次显式测速失败或超时时，列表显示最新失败状态和相对时间，例如 `超时 · 刚刚`，不得继续把旧成功延迟展示为当前结果。
- R15：CLI 增加 `mm node test --node <id> [--group <group>]`；指定 group 时必须校验节点属于该组，单节点请求只产生一个节点结果。

## Acceptance Criteria

- [ ] AC1：在真实或等价测试 daemon 流上，TUI 能展示测速进度以及成功、超时/失败结果。
- [ ] AC2：离开节点页或开始新的测速后，旧流被取消，旧结果不会污染新页面。
- [ ] AC3：最终行为与 README 和 TUI 文案一致，不再声称不存在的能力。
- [ ] AC4：进入节点切换列表不会产生延迟探测请求，并能立即显示已有历史结果或明确的“未测速”状态。
- [ ] AC5：单节点快捷键只测试光标所在节点，并更新该节点结果，不改变当前选择。
- [ ] AC6：批量测速快捷键测试当前代理组的可测速节点，逐项更新结果，不改变当前选择。
- [ ] AC7：历史结果展示包含最新延迟和相对时间；无 history 时显示“未测速”，不得把旧结果表现为刚刚完成。
- [ ] AC8：节点列表页脚显示 `t` 单测和 `a` 批量；快捷键只在该上下文生效，对“返回”等非节点项不发起测速。
- [ ] AC9：超过 120 个可测速节点的代理组不会被静默截断；完成事件的总数与实际候选数一致。
- [ ] AC10：单测或批量进行中按 `Esc` 后请求上下文被取消、页面不退出、部分结果仍可查看；再次按 `Esc` 才返回。
- [ ] AC11：有旧成功 history 的节点在最新探测失败后显示失败/超时及相对时间，不显示旧成功延迟冒充最新结果。
- [ ] AC12：`mm node test --node <id>` 支持 text/NDJSON、超时和取消；带 `--group` 时拒绝不属于该组或不可测速的节点，且不会退化为整组测速。

## Out Of Scope

- 不改变 mihomo 的延迟测试 URL、超时协议或 controller API。
- 不持久化测速历史，不承诺测速结果跨 mihomo core 重启保留。
- 不自动停止、修改其他代理进程。
- 不根据测速结果自动切换节点。

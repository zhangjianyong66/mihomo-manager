# 域名与 IP 分流规则

## Goal

将现有仅支持直连域名的“白名单”升级为可管理直连和代理两类域名/IP 分流规则。用户可在不编辑 `config.yaml` 的情况下，为根域名及其子域名、单个 IPv4/IPv6 地址或 CIDR 网段指定流量出口。

## Background

- 现有白名单数据位于 `<CONFIG_DIR>/whitelist.yaml`，仅存储 `domains`，路由合成器将其渲染为 `DOMAIN-SUFFIX,<domain>,DIRECT`。
- `internal/mihomo/routing_policy.go` 的固定顺序为：本机/局域网、用户自定义规则、白名单、CN rule-set、`MATCH,🌐 代理`。
- `global` 模式绕过 mihomo 的 `rules`，因此本功能只在 `rule` 模式生效。
- 现有白名单修改验证并写入配置，但不会自动使已运行 Core 重载。

## Requirements

### R1. 规则类型与目标

- 提供“直连”和“代理”两类受管分流规则。
- 每类规则支持：域名、单个 IPv4/IPv6 地址、IPv4/IPv6 CIDR 网段。
- 域名输入允许裸域名、`*.` 前缀和误粘贴的 HTTP(S) URL；持久化时规范化为小写裸域名。
- 单个 IP 规范化为其完整 CIDR（IPv4 `/32`、IPv6 `/128`）。不接受带端口的地址或无效值。
- 域名一律使用 mihomo `DOMAIN-SUFFIX` 语义：`zhangjianyong.top` 同时匹配根域名及全部子域名。
- 代理规则目标固定为 `🌐 代理` 组当前选择的节点；不为单条规则选择固定节点。

### R2. 优先级与冲突

- 用户在 `config.yaml` 中手写的自定义路由规则始终优先于本功能生成的规则。
- 受管规则跨两类列表合并后按匹配范围从具体到宽泛渲染：更深的子域名优先于父域名，更长前缀的 CIDR 或单 IP 优先于较宽网段。
- 同一个规范化域名或相同网络不能同时出现在直连和代理两类规则中；保存时拒绝并显示冲突。
- 本机/局域网保护规则、CN rule-set 和末尾 `MATCH,🌐 代理` 的既有顺序不变。

### R3. 兼容与持久化

- 保留现有 `whitelist.yaml` 及旧白名单 CLI/API 能力；旧白名单内容迁移或兼容读取为直连规则。
- 订阅更新、路由预设和模式切换必须保留两类受管分流规则。
- 配置写入继续使用已有的备份、原生校验和失败恢复机制；禁止覆盖用户自定义规则。

### R4. 交互

- CLI 提供直连和代理规则的查询、新增、修改、删除能力，并遵循现有 table/JSON、profile 和退出码契约。
- CLI 默认只保存；使用 `--restart` 才在保存成功后立即重启 Core，避免在脚本中引入交互确认。
- TUI 将“白名单管理”改为“域名分流”，用户可进入直连或代理列表，并进行查询、新增、修改、删除。
- Core 处于 `running` 时，规则成功保存后提示是否重启 Core：确认则通过受管能力重启并报告结果；取消则保留已保存规则并告知下次启动生效。
- Core 已停止时不显示重启确认；保存后明确告知下次启动生效。
- `global` 和 `direct` 模式中，CLI/TUI 状态明确提示分流规则不生效。

## Out of Scope

- 不支持每条规则绑定独立节点或代理组。
- 不改变 `global`、`direct`、`rule` 的 mihomo 原生模式语义。
- 不接管或重排用户手写自定义规则。
- 不改变现有 CN 路由规则集和 DNS 合成策略。

## Acceptance Criteria

- [ ] 直连或代理配置 `zhangjianyong.top` 时，生成的 mihomo 规则匹配根域名及 `ecs.zhangjianyong.top` 等任意子域名。
- [ ] 可分别添加 IPv4、IPv6、单 IP 和 CIDR 到直连或代理列表，并生成正确的 `IP-CIDR`/`IP-CIDR6` 规则与目标。
- [ ] 子域名优先于其父域名，单 IP 或更长前缀 CIDR 优先于包含它的较宽网段，即使目标类别不同。
- [ ] 同一规范化规则跨直连/代理列表冲突时写入失败，文件和运行配置保持不变。
- [ ] 用户手写规则仍位于受管规则之前，并优先命中。
- [ ] 旧 `whitelist.yaml` 和旧白名单 CLI/API 仍可使用，旧条目作为直连规则生效。
- [ ] CLI 和 TUI 都能管理两类规则；CLI 的 JSON/table 和错误/退出码保持项目契约。
- [ ] CLI 默认不会因规则修改而重启 Core，带 `--restart` 时会在保存成功后重启。
- [ ] Core 运行时保存规则后提供重启确认，确认会重启 Core，取消不重启；Core 停止时不询问重启。
- [ ] 规则、订阅更新、路由预设、模式切换和 Core 重启相关回归测试通过；配置原生校验和失败恢复覆盖新增路径。

## Resolved Decisions

- 相同受管规则跨两类列表冲突时拒绝保存。
- 规则范围重叠允许共存，按具体性优先。
- 代理规则始终走 `🌐 代理` 组。
- 原“白名单管理”升级为“域名分流”；旧入口作为兼容层保留。
- 保存规则后仅在 Core 正在运行时询问是否重启。

# 对齐 v2rayN 的终端 CLI 能力

## Goal

将 `mihomo-manager` 演进为面向终端用户的代理客户端管理器，以 v2rayN 的用户能力为对照基线。用户无需桌面 GUI，即可在本地终端、SSH 和自动化脚本中完成代理配置、订阅、节点、路由、运行状态和诊断等工作。

首要用户是 Linux 高级用户、SSH/无桌面环境和自动化调用者；个人 Linux 桌面用户是第二目标。发生优先级冲突时，无交互执行、远程诊断、服务化和机器可读状态优先于桌面集成。

## Current State

- 当前产品是 Go 1.22 mihomo 专用 TUI；无参数 `mm` 打开 Bubble Tea，Cobra 没有稳定业务子命令。
- 已有服务启停/重启/重载/配置测试、日志、代理组与节点切换、并发延迟测试、单订阅更新、白名单、路由诊断、配置备份/恢复/编辑和 CN 分流。
- 订阅支持完整 YAML，以及纯文本/base64 的 `vless://`、`vmess://`、`trojan://`、`ss://` 节点列表。
- 当前只有一份 `~/.config/mihomo/config.yaml`，业务集中于约 1550 行 `internal/mihomo/client.go`，TUI 集中于约 1140 行 `internal/tui/model.go`。
- 安装范围是 Ubuntu/Debian amd64、arm64；core 是独立 mihomo 二进制，安装构建保持 `CGO_ENABLED=0`。
- v2rayN 是 GPL-3.0 桌面多内核管理器，覆盖多订阅/节点格式、配置生成、路由/DNS、TUN、系统代理、测试、连接/流量、更新、二维码和 WebDAV。

## Product Decisions

- 产品定位为可扩展多内核的终端管理器，但 2.x 只交付 mihomo；3.0 先接 Xray，再接 sing-box。
- 非交互 CLI 是唯一稳定产品契约，TUI 只复用同一应用服务；无参数 `mm` 在 2.x 继续打开 TUI。
- 可管理数据使用规范化模型作为事实源，并由 core 适配器生成运行配置。
- 用户完整配置使用只读 `external` 模式；现有 1.x 配置使用仅限 2.x 迁移的 `legacy` 兼容模式。
- 用户级 daemon 是运行状态和写操作唯一所有者；CLI/TUI 通过本机 Unix socket 访问。
- 只承诺 Ubuntu/Debian amd64、arm64；Windows、macOS 和其他 Linux 发行版不进入首期验收。
- 采用“终端用户结果对齐”，不复制 GUI；托盘、主题、窗口热键和剪贴板监听永久排除。
- daemon/core 不长期 root；TUN 权限通过可预览、可撤销的一次性显式提权配置。
- 多命名档案、单活动实例；多订阅按来源隔离，手工节点属于独立来源。
- 首期不自建本地静态加密；依赖文件权限和默认脱敏。备份/同步单独使用加密包。
- 更新默认只检查，显式安装并可回滚；无人值守安装逐项选择性开启。
- 项目采用 MIT，不复制或改写 v2rayN GPL-3.0 源码，第三方组件单独记录许可证。
- 不设日历期限，发布由迁移、回滚、安全和自动化质量门驱动。

## Requirements

### 产品与接口

- R1：建立 v2rayN 与当前项目的能力矩阵，逐项标明已有、部分、缺失、排除、优先级和目标里程碑。
- R2：core 管理、配置生成和运行接口允许后续接入多内核；2.x 只要求 mihomo 达到生产可用。
- R3：所有核心能力先提供可脚本化命令；查询统一支持 `--output table|json`，流式操作支持文本/NDJSON，退出码和 JSON 字段纳入兼容约束。
- R3.1：无交互、SSH、诊断、服务化和机器可读状态优先于系统代理、PAC、二维码等桌面辅助。
- R3.2：TUI、CLI 不得分别实现业务逻辑；二者复用应用服务。2.x 保持无参数 `mm` 打开 TUI，并提供显式 `mm tui`。
- R4：能力边界覆盖档案、订阅、节点、导入导出、core 生命周期/更新、路由、DNS、TUN、系统代理、测试、连接/流量、备份同步、诊断和日志。
- R5：按可独立验收的里程碑/子任务交付，不采用全量重写。
- R6：升级不得静默覆盖用户配置或泄露敏感信息，2.x 必须保留 1.x 回退路径。
- R7：每个里程碑定义下载校验、凭据/日志、权限提升、迁移和回滚的安全边界。

### Daemon、平台与运行

- R8：IPC 校验同用户访问、协商协议版本；daemon 不可用时返回可诊断错误，不回退到多进程直接写状态。
- R9：daemon/core 崩溃恢复使用退避与熔断，异常退出不得遗留不可识别写入或虚假运行状态。
- R10：首期仅支持 Ubuntu/Debian amd64、arm64；不支持的平台明确报错，平台实现保留后续扩展边界。
- R17：socket 位于用户运行目录或等价的 `0700` 目录，socket 为 `0600` 并校验 peer UID；不得监听 TCP。
- R18：远程管理通过 SSH 执行同一 CLI/JSON/退出码，不新增远程业务协议。
- R19：不得安装 setuid、写宽泛 sudoers 或由 daemon 隐式请求 sudo；提权配置必须可预览、可撤销。
- R20：core 更新导致 TUN 权限失效时明确报告并要求重新显式配置，不得静默继承或扩大权限。

### 2.0.0-alpha.1 架构基线

- R11：Alpha 纵向打通 daemon、Unix socket、systemd user service、规范化存储、mihomo 适配器、配置生成、CLI/JSON、共享服务 TUI、安装升级和回滚。
- R11.1：正常 systemd user 会话中默认安装并启用 `mm.socket` 以按需激活 daemon，但不启动 proxy core；支持显式跳过，systemd 不可用时提供前台运行指引。
- R12：Alpha 为当前服务、节点/代理组、单订阅、白名单、路由诊断、配置、测速和日志提供行为等价迁移；TUN、流量/连接、系统代理和新 core 不作为 Alpha 完成条件。
- R13：新状态默认写入 `~/.local/share/mihomo-manager`，生成配置使用独立运行目录；不得覆盖 `~/.config/mihomo/config.yaml` 作为生成目标。
- R14：2.x 保留 `CONFIG_DIR`、`MIHOMO_BIN`、`MIHOMO_API_PORT`、`EDITOR`；迁移自动备份、可重复、可回滚。
- R14.1：无法可靠判断现有配置归属时创建 `legacy` 或 `external` 档案，不猜测转换；`legacy` 保留 1.x 行为，`external` 永不写回。

### 对齐与排除

- R15：对齐按终端中能否完成同类用户任务验收，不要求复制 v2rayN 界面表现。
- R16：永久排除托盘、窗口布局/主题、GUI 热键、窗口行为和剪贴板监听；二维码只做终端显示和图片文件解析，不做摄像头扫描。

### 档案、订阅与配置

- R21：档案切换先生成并验证候选，再停止旧实例；启动失败恢复上一档案或进入明确停止/失败状态。
- R22：端口、TUN、系统代理、日志、流量和连接归属于唯一活动档案；2.x 不支持并行 core 实例。
- R23：订阅/节点使用稳定 ID；更新只事务替换自身来源，失败保留上一成功版本。
- R24：允许来源间节点重名；展示标识来源，生成时使用确定性唯一名称，不修改其他来源解决冲突。
- R25：删除订阅不影响其他来源或手工节点；级联删除必须先预览范围。
- R32：生成顺序固定为规范化模型、路由/DNS 预设与规则、core 专属覆盖层、冲突/schema 验证、core 原生验证。
- R33：提供 `config render|diff|validate`；覆盖管理字段或所有权冲突必须报错。
- R34：专家覆盖层按档案/core 隔离，导出时标明类型；切换 core 不自动转换或静默忽略。

### 安全、更新与许可证

- R26：状态目录 `0700`，含敏感信息的数据库、配置、备份和日志为 `0600`，创建、启动和迁移后均校验。
- R27：表格、JSON、日志和错误默认不输出订阅令牌、UUID、密码等秘密；完整显示必须显式 `--show-secrets`。
- R28：普通配置导出不包含同步凭据；备份/同步密钥管理在 2.2 独立实现。
- R29：`update app|core|rules` 下载到临时位置，校验可信来源/摘要，验证后原子切换并保留上一版本。
- R30：更新失败不替换在用产物，core 更新不隐式继承 TUN 权限。
- R31：自动检查和自动安装分别配置、逐对象启用；默认关闭无人值守安装。
- R46：正式发布加入 MIT 文本和第三方许可证清单，清晰区分项目代码与独立下载/执行的第三方 core。

### 路线与发布

- R35：每个里程碑先在 mihomo 上端到端验收；3.0 前不得让多内核抽象阻塞 mihomo 用户能力。
- R36：3.0 接入顺序为 Xray、sing-box；其他单协议 core 未承诺，必须另立需求。
- R47：不设置日历发布期限；质量门失败时缩小或推迟里程碑，不降低迁移、回滚、安全或测试要求。
- R48：当前任务是总体规划父任务；实施从 Alpha 的第一个独立子任务开始，依赖关系写入每个子任务工件。

### 隐私、备份与桌面辅助

- R37：只持久化档案/节点/日期聚合流量，默认保留 30 天，可关闭/调整，不能反推单次目标。
- R38：日志脱敏，默认 7 天且总量不超过 50 MiB；提供 `privacy purge`。
- R39：实时连接明细只在 daemon 内存，不持久化域名、目标 IP、进程和单次连接。
- R40：备份包含档案、订阅、节点、规则和必要设置，不包含日志、流量、core、同步凭据和本机权限。
- R41：恢复先验证版本/完整性、展示变更并创建恢复点；冲突默认停止，不做字段级自动合并。
- R42：`backup export|import` 与远端协议无关；`sync push|pull` 通过适配器工作，WebDAV 是第一个后端。
- R43：`proxy env` 输出可审阅的 shell 设置/取消指令，不修改 shell 配置。
- R44：GNOME 系统代理启用前保存全部原设置，关闭时精确恢复；SSH/无桌面不得自动修改。
- R45：KDE、其他桌面和 PAC 不属于首个系统代理适配器验收，后续独立交付。

## Milestones

1. `2.0.0-alpha.1`：架构基线与现有能力等价迁移。
2. `2.0 Beta`：多档案、多订阅/手工节点、路由/DNS、覆盖层、managed 转换和导入导出。
3. `2.1`：TUN、连接/流量、测速增强、健康检查和诊断。
4. `2.2`：应用/core/规则更新、定时任务、加密备份、WebDAV 同步。
5. `2.3`：shell/GNOME 系统代理、PAC、终端二维码。
6. `3.0`：先 Xray，后 sing-box。

## Acceptance Criteria

- AC1（R1/R15/R16）：`research/capability-matrix.md` 覆盖 v2rayN 主要用户能力，每项有当前状态、目标版本或永久排除结论。
- AC2（R2-R10/R17-R20）：`design.md` 定义 CLI/TUI/daemon/core/store/platform 边界、IPC 协议、普通用户权限和远程访问边界。
- AC3（R3/R3.2/R27）：设计定义命令树、table/json/NDJSON、结构化错误、退出码和秘密展示规则；A1 计划包含契约测试。
- AC4（R11-R14.1）：`implement.md` 把 Alpha 拆为可独立验收子任务，包含 legacy/external/managed、迁移/回滚、安装和现有能力等价门。
- AC5（R21-R25/R32-R34）：设计定义单活动实例、订阅来源事务、确定性重名、生成顺序、覆盖层和失败恢复。
- AC6（R26-R31/R37-R42/R46）：安全、隐私、更新、备份、许可证均有默认安全行为、失败停止和回滚要求。
- AC7（R35/R36/R43-R45/R47/R48）：实施计划按已确认版本顺序拆分，明确依赖、进入门、完成门、停止条件，不使用日历期限替代质量门。
- AC8：PRD、设计、实施计划和研究文件不存在未解决范围问题或互相矛盾的产品边界。
- AC9：用户审阅规划工件并明确批准后，才创建/启动第一个实施子任务；当前父任务不直接启动全量实现。

## Out Of Scope

- 当前规划任务不修改业务代码、不启动 daemon/core、不迁移真实用户数据。
- 不复制、翻译或移植 v2rayN 的 GPL-3.0 源码。
- Alpha 不增加 TUN、连接/流量、系统代理、新 core 等用户能力。
- 2.x 不支持并行 core 实例、不开放 TCP 管理 API、不承诺 Ubuntu/Debian amd64/arm64 以外平台。
- 首期不自建本地静态加密，不持久化完整连接历史。
- 托盘、窗口/主题、GUI 热键、剪贴板监听和摄像头扫码永久排除。
- Xray、sing-box 以外的其他 core 不属于已承诺路线。

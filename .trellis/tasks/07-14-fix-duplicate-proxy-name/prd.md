# 修复 mihomo 配置重复节点名

## 目标

在不丢失节点、不覆盖无备份配置的前提下，修复 `~/.config/mihomo/config.yaml` 中重复的代理名称，使配置重新通过 mihomo 校验，并收紧配置文件权限。

## 已确认事实

- 当前配置包含 256 条代理。
- 共有 10 个重复名称，每个名称出现 2 次，节点参数不同，不能直接删除。
- 10 组重复节点均为 VLESS。
- 代理组 `🌐 代理` 中每个重复名称也恰好引用 2 次，可以与两个节点按出现顺序一一对应。
- mihomo v1.19.28 当前首先报告 `AI专用*23[专线]` 重名并拒绝配置。
- 当前配置权限为 `664`，文件可能包含节点凭据，应收紧为 `600`。
- 配置目录已有 `config.yaml.bak`，本次不能覆盖该备份。

## 需求

- 修改前创建带时间戳的新备份，不覆盖现有 `.bak`。
- 每组重复名称保留第一条原名，将第二条改为 `原名 (2)`；若未来出现更多重复，依次使用 `(3)`、`(4)`。
- 在每个代理组中按出现顺序同步重命名重复引用，确保所有节点仍可选择。
- 不修改节点服务器、端口、UUID、TLS 等连接参数。
- 候选配置必须先在临时文件中通过 mihomo 校验，再原子替换正式配置。
- 正式配置权限设置为 `600`。
- 校验或写入失败时保留原配置，并清理无效临时文件。
- 不自动重启当前运行中的 mihomo，不修改系统代理。

## 验收标准

- [x] 10 个重复名称均被消除，代理总数仍为 256。
- [x] `🌐 代理` 中两个节点引用均保留且名称与代理定义一致。
- [x] `mihomo -t -d ~/.config/mihomo -f ~/.config/mihomo/config.yaml` 成功。
- [x] 修改前配置有独立的时间戳备份。
- [x] 正式配置权限为 `600`。
- [x] 未启动、停止或重启 mihomo 进程。

## 实施结果

- 修复 10 组重复名称，第二条节点及对应组引用增加 `(2)` 后缀。
- 代理总数保持 256，重复名称和未解析组引用均为 0。
- 修复前备份：`~/.config/mihomo/config.yaml.20260714_214929.bak`。
- 正式配置和备份权限均为 `600`。
- 当前 mihomo 未运行；`10808` 由 xray 占用，未对运行态做任何变更。

## 不在范围内

- 删除节点、测速或判断哪条重复节点更优。
- 更新订阅或改变路由规则。
- 重启 mihomo 或修改系统代理。
